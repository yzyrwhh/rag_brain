# 04 · 多智能体编排设计

> 核心章节。定义多智能体的图结构、角色职责、协作模式、人机回环、工具注册中心与记忆系统。技术栈：LangGraph（Supervisor-Worker 模式）+ LangSmith 追踪。

## 1. 总体编排模式

采用 **Supervisor-Worker + Plan-and-Execute + ReAct + Critic 反思** 的组合：

```
                     用户输入 (session + query + 上下文)
                                   │
                                   ▼
                    ┌────────────────────────────┐
                    │  Supervisor 主管图           │
                    │  1. 意图识别(JSON)           │
                    │  2. 安全审查(GuardAgent)     │
                    │  3. 路由到域 Agent / 直接答  │
                    └────────────┬───────────────┘
                                 │ 复杂任务?
                    ┌────────────┴─────────────┐
                    ▼                          ▼
        ┌────────────────────┐      ┌──────────────────────┐
        │ 域 Agent(Worker)    │      │ Planner(规划器)        │
        │ ReAct 工具循环       │      │ 分解为步骤树            │
        │ 简单任务直接完成      │      └──────────┬───────────┘
        └────────┬───────────┘                 ▼
                 │                    多个 Worker 并行/串行执行
                 ▼                    (LangGraph SubGraph)
        ┌────────────────────┐                 │
        │ Critic(反思器)      │◀────────────────┘
        │ 质量评审: 是否达标?  │──不达标──▶ 重试/补充检索/澄清
        └────────┬───────────┘
                 │ 达标
                 ▼
        ┌────────────────────┐
        │ 答案组装 + 引用 +   │
        │ 记忆写入(Memory)    │
        └────────────────────┘
```

**何时走哪条路（Supervisor 决策规则）：**

| 输入特征 | 路径 |
| :--- | :--- |
| 简单问答（问候、闲聊） | Supervisor 直接回复，不派工 |
| 单域查询（RAG 问答、代码咨询） | 直接路由到对应域 Agent |
| 多步骤/多工具任务（找论文→筛选→入库；综述） | Planner 分解 → 多 Worker 执行 |
| 需要外部决策（哪个商家好） | 执行中触发 `clarify`（HITL） |

## 2. Supervisor 主管设计

### 2.1 意图识别（替代现有硬编码 item_name_confirm）

每个请求先调用意图识别 LLM（qwen-flash，JSON 模式），输出：

```json
{
  "intent": "research_paper_search",        // 见意图枚举
  "domain": "paper",                        // knowledge/dev/research/life/general
  "task_type": "async",                     // sync|async
  "entities": {"topic": "RAG 优化", "limit": 10, "years": "2022-2025"},
  "requires_planning": true,
  "route_to": "research"
}
```

意图枚举（可扩展，注册在 `agents/intents.py`）：

```
knowledge_query | knowledge_import | knowledge_manage
dev_consult | dev_code | dev_case_save | dev_case_query
research_paper_search | research_paper_save | research_review
life_recommend | life_compare | life_list | life_preference
general_chat | clarification | cancel | help
```

- 未命中（置信度 < 0.6）→ 走 `clarify` 或 general_chat。
- 意图 → 路由表 `INTENT_ROUTES` 映射到域 Agent 与图入口。

### 2.2 GuardAgent（安全闸门，Supervisor 首节点）

- 输入：原始 query + 检索/工具上下文。
- 输出：`{risk: none|injection|sensitive, action: allow|redact|ask_confirm}`。
- 触发 `ask_confirm` 的操作：导入外部内容、写记忆、外链跳转、代码执行（阶段二）。
- 提示词规范：注入检测规则 + 工具调用白名单校验。

## 3. 域 Agent（Worker）设计

统一抽象 `BaseWorker`：

```python
class BaseWorker(Protocol):
    agent_id: str
    tools: list[ToolSpec]
    def build_graph(self) -> CompiledStateGraph: ...
    def system_prompt(self, ctx: AgentContext) -> str: ...
```

### 3.1 KnowledgeAgent（知识域，重构现有资产）

- **职责**：RAG 问答、文档导入、知识管理。
- **工具**：`kb_retrieve`（混合检索，支持 `mode=chunk|full`）、`kb_import`（文档入库，内部复用旧导入管线节点）、`graph_query`（图谱检索）、`kb_read_document`（全文加载）、`kb_list/search_docs`、`web_search`（可关闭）。
- **图结构**：ReAct 循环（工具调用 ≤ 5 轮）→ 检索 → 生成（带引用）。
- **迁移**：旧 `query_process` 的检索链路（HyDE/向量/Web → RRF → Rerank）折叠为 `kb_retrieve` 工具的一个内部实现；旧 `import_process` 折叠为 `kb_import` 工具（04.5 节给出伪代码）。

### 3.2 DevAgent（开发域）

- **职责**：
  1. 技术方案咨询：混合检索（个人经验库 + dev 域文档 + Web）→ 结构化方案输出（背景/方案对比/风险/落地步骤）。
  2. 代码生成/审查：上下文工程（需求 + 经验条目 + 相关代码）→ 生成；审查用 Critic 专项。
  3. 经验沉淀（US-2.3）：会话结束或用户说"记住"→ 提取 `dev_case` 记忆条目（技术栈、场景、决策、教训）→ 写入记忆系统。
  4. 外部 Agent 桥接（FR-28）：复杂/专业任务委托给第三方 Agent（Claude Code 等），产出回流为经验（详见 §11）。
  5. 设计知识咨询（FR-33）：问"记忆机制有哪些设计方案"→ 召回本项目沉淀的设计文档（Wiki 资产）+ ADR（L1 原子）+ 借鉴案例（TencentDB-Agent-Memory 等）→ 输出方案对比；实施+测试后把实际效果/踩坑回写为经验（版本化 supersedes），形成"设计→实施→验证→迭代"闭环。
- **工具**：`kb_retrieve(domain=dev)`、`graph_query`/`graph_mindmap`（技术栈图谱）、`codegraph`（代码符号/调用关系/影响分析，阶段二）、`memory_write`、`external_agent`（桥接，user_confirm）、`web_search`、`code_runner`（阶段二）。
- **关键体验**：答案必须标注"来自我的经验库 / 来自网络"，避免混淆。

### 3.3 ResearchAgent（研究域）

- **职责**：
  1. 论文检索：`paper_search`（arXiv API + Semantic Scholar API，领域/年份/引文过滤）→ 候选列表（标题/摘要/引用/来源）。
  2. 筛选评估：LLM 逐篇打分（相关度/方法新颖性/可复现性）→ 排序。
  3. 入库（US-3.2）：确认后 `paper_import`（下载 PDF → 复用导入管线 → domain=paper → 元数据写 Mongo）。
  4. 综述生成（US-3.3）：Planner 分解（按主题分组 → 逐组阅读入库论文 → 汇总）→ 多步执行 → Critic 校验引用一致性。
- **工具**：`paper_search`、`paper_fetch`、`kb_import`、`kb_retrieve(domain=paper)`、`web_search`。
- **多轮协作流程（FR-14 增强）**：论文检索/入库天然多轮——`需求澄清(范围/年限/评价标准) → 检索 → 候选展示 → 用户筛选/调整 → 再检索 → 入库确认(HITL) → 完成`；每轮以 `clarify` 事件驱动，用户可随时改口重搜；用户选择的候选与理由沉淀为 `preference` 记忆，后续检索自动加权。
- **合规**：优先官方 API；无 API 时抓取摘要页，遵守 robots.txt 与频率限制（NFR-10）。

### 3.4 LifeAgent（生活域）

- **职责**：
  1. 需求理解：从口语提取结构化需求（品类、数量、预算、口味/偏好、送达时间）。
  2. 比价检索：`shopping_search` 工具（聚合站点公开页面抓取/官方开放接口，缓存结果 30min）。
  3. 推荐清单：评分排序（价格/评分/距离）→ 输出清单（含外链）。
  4. 清单转记忆：用户采纳后，将偏好写入记忆（`preference`/`habit`）。
- **工具**：`shopping_search`、`memory_read`、`memory_write`、`web_search`。
- **边界（ADR-003）**：只输出推荐与链接；外链统一走 `redirect` 端点审计；不保存用户平台凭证。

## 4. Planner / Executor / Critic

### 4.1 Planner（规划器）

仅复杂任务触发（`requires_planning=true`）。输出步骤树（写入 `task.plan`，前端渲染）：

```json
{
  "objective": "对入库的 12 篇 RAG 论文生成综述",
  "steps": [
    {"id": "s1", "title": "按子主题分组论文", "agent": "research", "tool": "kb_retrieve", "deps": []},
    {"id": "s2", "title": "逐组提炼方法要点", "agent": "research", "tool": "llm_read", "deps": ["s1"]},
    {"id": "s3", "title": "汇总对比并生成综述草稿", "agent": "research", "tool": "compose", "deps": ["s2"]}
  ]
}
```

- 步骤可并行（无依赖关系）→ LangGraph `Send` API 扇出。
- 规划失败/步骤不可执行 → 回退为串行 ReAct。

### 4.2 Executor（执行器）

- 每个步骤一个子图；步骤间共享 **Blackboard**（图状态），取代旧 `TypedDict` 平铺：
  ```python
  class Blackboard(TypedDict):
      user_id: str; session_id: str; task_id: str
      input: dict; plan: list; results: dict      # step_id -> result
      events: list; budget: Budget; cost: Cost
      clarifications: list; interrupted: bool
  ```
- 节点通过 `push_event(state, type, payload)` 统一发事件（写 Mongo + 推 Redis/SSE）。

### 4.3 Critic（反思器）

每个域 Agent 完成产出后（可选开启）评审：

| 维度 | 检查项 |
| :--- | :--- |
| 完整性 | 是否覆盖用户所有子需求（对照 entities） |
| 正确性 | 引用是否真实存在、事实是否与检索结果一致 |
| 安全 | 是否输出敏感/越权内容 |
| 格式 | 是否满足输出 schema（清单/方案/综述结构） |

- 输出 `{score: 0-1, issues: [...], action: accept|retry|clarify}`。
- `retry`：带 issues 回到执行器重试（≤ 2 次）；`clarify`：生成澄清问题给用户。
- 成本控制：Critic 仅对 `async` 任务与高质量需求（用户标记/评分低反馈）开启。

## 5. 人机回环（HITL）

- 触发点：`clarify`（歧义/多选）、`confirm`（敏感操作：导入、写记忆、外链）、Critic 的 `clarify`。
- 机制：LangGraph `interrupt()`（checkpoint 持久化）→ 任务状态 `AWAITING_INPUT` → 前端渲染选项按钮 → 用户选择 → `POST /tasks/{id}/respond` → 图从断点恢复。
- 协议（事件 `clarify`）：
  ```json
  {"question": "推荐哪个方向的方案？", "options": [
     {"id": "o1", "label": "偏 LangGraph 原生实现"},
     {"id": "o2", "label": "偏轻量自研编排"}]}
  ```
- 超时：24h 未答复 → 任务按默认选项继续或取消（agent 配置决定）。

## 6. 工具注册中心（MCP）

### 6.1 架构

```
Agent 图节点 (ReAct/tool calling)
        │ 通过 LangChain ToolNode 调用
        ▼
┌──────────────────────────┐
│ ToolRegistry（注册中心）    │  ── builtin: kb_retrieve/kb_import/web_search/...
│  - 工具清单(tool_registry) │  ── mcp:   MCPClient(stdio/SSE) 连接外部 MCP server
│  - 权限校验(permission)    │       (DashScope WebSearch MCP 等)
│  - 调用审计/限流/缓存       │
└──────────────────────────┘
```

### 6.2 内置工具清单（v1）

| tool_id | 说明 | permission |
| :--- | :--- | :--- |
| kb_retrieve | 混合检索（空间/域过滤 + RRF + Rerank） | public |
| kb_import | 文档导入（文件/URL/论文） | user_confirm |
| kb_search_docs | 文档元数据搜索 | public |
| web_search | Web 搜索（DashScope MCP / Tavily 备选） | public |
| web_fetch | 抓取网页正文（限域名单 + 频率限制） | public |
| paper_search | arXiv/S2 论文检索 | public |
| paper_fetch | 下载论文 PDF | user_confirm |
| memory_write | 写语义记忆 | user_confirm |
| memory_read | 检索语义记忆 | public |
| shopping_search | 生活比价检索 | public |
| graph_query | 图谱检索（实体/关系/多跳） | public |
| graph_mindmap | 主题脑图/子图投影（返回树形 JSON） | public |
| kb_read_document | 全文读取（预算内分节/整篇，FR-27） | public |
| external_agent | 调用第三方 Agent（Claude Code 等，FR-28） | user_confirm |
| code_runner | Docker 沙箱执行代码 | user_confirm（阶段二） |

### 6.3 MCP 接入规范

- 客户端支持 stdio 与 SSE 两种传输；配置存 `tool_registry`（mcp_endpoint）。
- 工具 schema 由 MCP server 的 `list_tools` 动态拉取，写入 `input_schema`。
- 调用超时 30s；失败自动标记不可用并降级（LLM 提示重试其他工具）。
- 安全：MCP server 默认最小权限沙箱运行（无宿主网络访问权限，阶段二加固）。

### 6.4 工具库（Tool Library）

工具不仅是"可调用函数"，更是**可治理的资产目录**：

| 维度 | 设计 |
| :--- | :--- |
| 分类 | 检索类 / 知识类 / 研究类 / 生活类 / 开发类 / 桥接类（`tool_registry.category`） |
| 描述质量 | LLM 感知的 `description` 即"文档"：统一由工具作者维护，PR 评审时检查（描述差 → 调用准确率低） |
| 按 Agent 分配 | `agent_configs.enabled_tools` 白名单；`GET /tools/recommend?agent=` 给出推荐工具集 |
| 使用统计 | `tool_registry.stats`（调用次数/成功率/平均耗时/token 成本），定期整理出"低频低质"工具并提示下线 |
| 版本与灰度 | 工具实现版本化，MCP 工具以 endpoint 维度整体升级；新工具先 `beta` 标记 |
| 测试 | 每个内置工具必须带契约测试（输入 schema 校验 + 输出归一化）与 mock 测试（07 文档） |

## 7. 记忆系统

### 7.1 四类记忆

| 类型 | 载体 | 生命周期 | 说明 |
| :--- | :--- | :--- | :--- |
| 工作记忆 | LangGraph 图状态（Blackboard） | 任务内 | 当前任务上下文、中间结果 |
| 情景记忆 | Mongo `sessions`/`messages`/`tasks` | 持久 | 发生过什么：对话、任务、反馈 |
| 语义记忆 | Mongo `memories` + Milvus `memory_vectors` | 持久可编辑 | 长期事实/偏好/经验，显式管理（前端可增删改） |
| 程序记忆 | Mongo `agent_configs` + prompts 注册表 | 版本化 | 怎么做：Agent 技能、提示词、工具配置 |

**分层记忆映射（借鉴 TencentDB-Agent-Memory L0–L3，ADR-016）**：四类记忆映射到其渐进四层，落地采用"分层沉淀 + 渐进召回"，避免一次性把记忆塞满上下文：

| 层 | 我们的载体 | 语义 |
| :--- | :--- | :--- |
| L0 Conversation | Mongo `messages` | 原始对话原文，可溯源核对 |
| L1 Atom | Mongo `memories` + Milvus `memory_vectors` | 事实/偏好/约束/事件/点子（结构化：type + 活动时间 + source_message_ids） |
| L2 Scenario | 情景记忆的任务拓扑（Mermaid 状态机） | 一个项目/主题的认知状态：目标、进度、done/doing/blocked、雷区 |
| L3 Core/Persona | `memories(kind=persona)` 常驻 | 长期画像、稳定模式、核心偏好（importance=5，禁衰减） |

### 7.2 语义记忆读写

- **写入策略（Anthropic 式为主，防噪音）**：① **用户显式**（"记住：我偏好 X"）→ 直接落库（trust=1.0）；② **Agent 半自动提议**（识别到高价值信息时问"要我记住吗？"）→ 用户确认后落库；③ **纯自动抽取仅限高价值低频场景**（dev_case / design_decision，会话结束批量提取，置信度 < 0.7 不落库 🧪）。禁止对日常对话做全量自动抽取——注入噪音是记忆系统的头号负资产（详见 08 §5 R13）。
- **点子/进展捕获（FR-30/31）**：用户说"记下这个点子/这个不错"或 Agent 识别到高价值想法/困惑时，走 `memory_write(kind=idea|insight|progress)` 结构化存储并 `linked_ids` 关联 Paper/文档/任务；学习进展（"读到 XX 第 3 章""卡在 YY"）按主题聚合为 `progress` 条目，跨会话可恢复。
- **经验资产化（FR-32/33）**：DevAgent 经验不只是一个文本条目，而是 **Skill 资产**——含 `version`（不可变快照）、`content_hash`、`manifest`（资源文件）、触发边界、执行步骤、验证规则；两阶段去重（propose → 相似经验提示 → 确认）；新版本 `supersedes` 旧版本。
- **渐进式召回（借鉴 auto-recall）**：三段注入而非一次 top-5——① L3 persona 常驻 system 提示（稳定，可缓存）；② L2 场景导航（**只注入目录+摘要，不注入全文**，防 system 膨胀破坏缓存）；③ L1 按查询召回（user 前缀，每轮变）。召回受预算约束：`max_results=5`（**默认注入 3 条，噪音防护 🧪**）、`score_threshold=0.3`、`max_chars_per_memory`、`max_total_chars`、`timeout=5s`（🧪 均需评测校准，见 08 §8.1 #2）；注入片段不足时 Agent 主动调 `memory_search`/`conversation_search` 工具（每轮 ≤3 次）回 L1/L0 取精确事实。
- **任务延续判定（L1.5）**：长任务生成任务拓扑；新会话首轮判定 `taskCompleted/isContinuation/continuationFile`，命中则注入历史进度/阻塞点，直接回答"我上次进展到哪"（FR-30）。
- **去重/冲突**：相似记忆（向量相似度 > 0.9）合并或提示用户；同一主题最新优先。
- **遗忘**：用户删除、TTL 到期、注销级联删除（NFR-10）。

### 7.3 MemoryManager（记忆管理智能体）

- 独立的记忆写入/整理节点，挂在工作流末尾与用户显式指令时。
- **任务延续判定（L1.5）**：维护"活跃任务拓扑"，新会话首轮输出 taskCompleted/isContinuation/continuationFile，命中则恢复注入（FR-30）。
- **定期整理（FR-29，Phase 4 落地）**：夜间任务执行 03 §10.1 的记忆生命周期流程——情景摘要、语义去重合并、冲突消解、重要性衰减、TTL 过期、经验 supersedes 标记、实体抽取→图谱链接、进展追踪更新；幂等可重放，产出写审计。
- 整理结果通知：影响用户可见记忆时（如合并/降权）在下次会话注入轻量提示（"你的 3 条经验已合并为 1 条"）。

## 8. LangGraph 图结构示例（伪代码）

```python
# server/app/agents/graphs/supervisor_graph.py
from langgraph.graph import StateGraph, END, START
from langgraph.checkpoint.memory import InMemorySaver  # 阶段一; 生产用 Mongo/Redis saver

def build_supervisor_graph(registry: ToolRegistry, memory: MemoryManager):
    g = StateGraph(Blackboard)

    g.add_node("guard", guard_node)                    # GuardAgent
    g.add_node("intent", intent_node)                  # Supervisor 意图识别
    g.add_node("knowledge", KnowledgeAgent(registry, memory).build_graph())
    g.add_node("dev", DevAgent(registry, memory).build_graph())
    g.add_node("research", ResearchAgent(registry, memory).build_graph())
    g.add_node("life", LifeAgent(registry, memory).build_graph())
    g.add_node("planner", planner_node)                # Plan-and-Execute
    g.add_node("critic", critic_node)                  # Critic 反思

    g.add_edge(START, "guard")
    g.add_edge("guard", "intent")
    g.add_conditional_edges("intent", route_intent, {
        "knowledge": "knowledge", "dev": "dev", "research": "research",
        "life": "life", "general": "direct_answer",
        "complex": "planner", "clarify": "clarify_node"})
    g.add_edge("planner", "research")   # 示例: 综述走 research 多步执行
    g.add_edge("knowledge", "critic")
    g.add_edge("critic", "finish")      # finish 节点: 组装答案 + 记忆写入 + 发完成事件
    return g.compile(checkpointer=saver)
```

要点：
- 域 Agent 是**子图**（SubGraph），内部 ReAct 循环独立成图，通过 `interrupt` 支持 HITL。
- 每个节点首行 `push_event(state, ...)`，保证前端进度真实可观测。
- 图编译时注入 `checkpointer`（生产用 `langgraph-checkpoint-mongo` 或 Redis），支撑断点恢复与 `AWAITING_INPUT`。

### 8.1 Blackboard 状态字段（实现契约）

```python
class Blackboard(TypedDict):
    # 身份与追踪
    user_id: str; session_id: str; task_id: str; message_id: str
    # 输入
    input: dict            # {query, entities, attachments, spaces[]}
    intent: str            # 意图枚举（04 §2.1）
    domain: str            # knowledge/dev/research/life/general
    task_type: str         # sync | async
    # 规划与执行
    plan: list[dict]       # [{step_id, title, agent, tool, deps[]}]
    current_step: str
    results: dict          # step_id -> result（Blackboard 共享）
    # 检索/图谱/全文
    retrieved_chunks: list[dict]; graph_hits: list[dict]; fulltext: str | None
    tool_results: list[dict]   # [{tool_id, ok, summary, cost}]
    # 记忆
    recalled: dict         # {persona, scene_nav, l1_lines[]}
    memories_written: list[str]
    # HITL
    clarifications: list[dict]  # [{clarify_id, question, options[], answer}]
    interrupted: bool
    # 预算与成本
    budget: dict           # {max_tokens, max_steps, timeout, used_tokens, steps}
    cost: dict             # {tokens, estimated_cost}
    # 输出
    answer: str | None
    sources: list[dict]
    # 事件（节点用 push_event 追加，不直接操作）
    events: list[dict]
```

### 8.2 节点契约（输入 → 输出 → 副作用 → 事件）

| 节点 | 输入 | 输出 | 副作用 | 事件 |
| :--- | :--- | :--- | :--- | :--- |
| guard | input.query + 上下文 | {risk, action(allow/redact/ask_confirm)} | 高风险写审计 | agent.thinking(可选) |
| intent | input | {intent, domain, task_type, entities, route_to, confidence} | 写 tasks.intent | task.plan（复杂任务时） |
| knowledge/dev/research/life | Blackboard | answer/results + tool_results | 写记忆、发消息 | node.start/end、tool.call/result、message.delta |
| planner | input | plan[] | 写 tasks.plan | task.plan |
| critic | answer + retrieved | {score, issues[], action(accept/retry/clarify)} | retry→重跑执行子图 | agent.thinking |
| clarify_node | clarifications | interrupted=True | 任务置 AWAITING_INPUT + checkpoint | clarify |
| finish | answer + sources | 最终消息 | 写 message、记忆沉淀、cost 落库 | message.final、task.completed |

**节点通用约定**：① 每个节点第一行 `push_event(state, type, payload)`；② 所有 LLM 调用走 `LLMClient`（07 §7.1），带预算与超时；③ 任何节点抛异常 → 上层转 `task.failed`（retryable 标记），不静默吞错。

### 8.4 HITL interrupt 实现要点

```python
# 澄清节点内（LangGraph interrupt 模式）
from langgraph.types import interrupt, Command

def clarify_node(state):
    question, options = build_clarify(state)
    answer = interrupt({"clarify_id": gen_id(), "question": question, "options": options})
    # 任务状态置 AWAITING_INPUT 由 checkpointer 持久化；恢复时从 interrupt 处继续
    return {"clarifications": [*state["clarifications"], answer], "interrupted": False}

# 恢复入口：POST /tasks/{id}/respond → resume(task_id, Command(resume=payload))
# 前端收到 clarify 事件 → 渲染选项 → 用户选择 → respond → graph.resume
```

## 9. 并发与资源控制

| 维度 | 策略 |
| :--- | :--- |
| 用户级并发 | 每用户同时 ≤ 3 个活跃任务（超限排队，Redis 队列） |
| Worker 并发 | Celery 每 worker 2 进程 × 4 并发；LLM 限流（QPS 按模型） |
| 预算 | 每任务 token/step/timeout 预算（02 文档 3.2），超额降级 |
| 工具调用 | 每任务工具调用 ≤ 15 次；同工具连续失败 ≥ 3 次自动停用该工具 |
| LLM 缓存 | 相同意图+查询的意图识别/检索摘要缓存（Redis, TTL 24h） |
| 沙箱 | 代码执行仅限 Docker 沙箱容器（CPU/内存/网络受限） |

## 11. 外部 Agent 桥接（ExternalAgentGateway，FR-28）

### 11.1 目标

DevAgent 的能力上限 = 自研工具 + 自研提示词。桥接层让它可以**委托更专业、更新、更细粒度的第三方 Agent**（Claude Code、Cursor Agent、自建 MCP Agent 等），并把产出回流为经验。

### 11.2 两种桥接方向

| 方向 | 说明 | 实现 |
| :--- | :--- | :--- |
| 出站（本系统 → 第三方） | DevAgent 把任务委托给 Claude Code 等 | `external_agent` 工具：适配器 → 子进程(CLI)/API → 结果归一化 |
| 入站（第三方 → 本系统） | Claude Code 等在工作时查询掌柜智库知识/经验 | 本系统作为 **MCP server** 暴露 `kb_retrieve`/`memory_read`/`graph_query` 工具，第三方通过 MCP 接入 |

### 11.3 出站桥接设计

```
用户确认(user_confirm) → DevAgent 组包(任务+上下文+预算) → ExternalAgentGateway
  → 适配器(Adapter): ClaudeCodeAdapter / MCPClientAdapter / CustomAPIAdapter
  → 执行: Docker 沙箱内子进程(隔离) / MCP 调用 / HTTP
  → 结果归一化: {output, files[], cost, duration, exit_code}
  → Critic 评审 → 汇总给用户；用户采纳 → 摘要沉淀为 dev_case(source=external_agent)
```

- **适配器抽象**：`ExternalAgentAdapter(Protocol)`（name/check_available/invoke/stream_events），新增第三方只实现一个适配器 + 注册 `integrations` 配置。
- **配置与密钥**：provider=claude_code 等存 `integrations`（加密），模型/命令/预算可配。
- **安全**：子进程运行在 Docker 沙箱（无宿主网络写权限、CPU/内存受限、超时强杀）；不传递用户凭证；敏感输出脱敏；全程审计；每次调用需用户确认（permission=user_confirm）。
- **流式体验**：第三方 Agent 的步骤/输出经 `tool.call`/`agent.thinking` 事件透传给前端（LLM 转发摘要，避免原始流泄漏细节）。
- **成本**：外部 Agent 费用按次估算记入 `tasks.cost`（provider 维度），纳入用户月限额。

### 11.4 经验回流（自迭代）

外部 Agent 产出经 Critic 评审 → 用户采纳/打分 → `memory_write(kind=dev_case, source=external_agent, linked_task)` → 进入 03 §10 的经验质量闭环（去重/supersedes/importance）。多次委托同一类任务时，DevAgent 优先检索此前外部 Agent 沉淀的经验，逐步"把外部能力内化"，减少重复委托。

## 12. 图谱增强检索与全文工具（对接 03 §8/§9）

- **混合检索升级**：`kb_retrieve` 内部 = 向量召回 + 图谱实体扩展（1-2 跳）+ RRF 融合（03 §8.4）；查询涉及技术栈/论文/概念关系时优先走图谱路径。
