# 智能产品知识库系统详细设计

> **文档说明**：本文档基于当前实际代码整理（单应用架构），与 `knowledge/` 目录下的实现一致。
> 早期规划稿中的"RAG 工具化（kb_upload/kb_retrieve + 主 Agent 编排 + Celery/Redis）"方案已废弃，
> 相关 server 目录已移除，本文不再收录。

## 1. 系统定位

**智能产品知识库**面向产品资料问答场景：

- **输入**：上传产品说明书、产品描述、产品介绍等文档，支持 **PDF、Markdown** 两种格式
  （其他类型在上传入口直接校验拒绝）。
- **处理**：文档自动解析、图表理解、切片、向量化入库；同时识别文档核心产品名，登记入产品名索引。
- **输出**：用户用自然语言提问（如"如何使用万用表测量电压？"），系统从库内检索相关内容，
  由大模型生成带**引用来源**的回答，支持流式输出与多会话历史。

### 1.1 当前明确不做（边界）

| 能力 | 状态 | 说明 |
| :--- | :--- | :--- |
| 多租户/空间隔离 | 未启用 | 早期规划的 space/members 体系未进入最终实现 |
| 用户体系/登录鉴权 | 未启用 | 面向本地/单机部署 |
| 知识图谱问答 | 未启用 | Neo4j 相关配置保留默认空值，问答图不含图谱节点 |
| Word/Excel 等格式 | 不支持 | 仅 PDF / Markdown（见 §8 改进方向） |

## 2. 总体架构

单应用 FastAPI 服务：**页面托管 + 统一 HTTP API** 一体，运行在 `8001` 端口；
业务编排使用 **LangGraph** 双图（文档导入图、智能问答图）；存储使用 **Milvus + MongoDB + MinIO**。

```
用户（浏览器）
   │  HTTP（页面 + JSON + SSE 流式）
   ▼
┌──────────────── 智能产品知识库（FastAPI :8001） ────────────────┐
│  knowledge/front/api/main.py       统一 API 入口 / 页面托管        │
│  ├─ 导入流程 → import_process 导入图（LangGraph）                 │
│  ├─ 问答流程 → query_process  问答图（LangGraph）                 │
│  ├─ prompt / tools / utils         提示词、工具、基础设施          │
└──────────┬──────────────┬──────────────┬──────────────┬─────────┘
           ▼              ▼              ▼              ▼
        Milvus         MongoDB          MinIO         LLM / MCP
      向量(切片/产品名)   会话历史/文档注册    解析产物图片    OpenAI 兼容 / 联网检索
```

**基础组件**（`docker compose up -d`）：etcd、minio、milvus（standalone）、attu（Milvus GUI）、mongodb。

**启动方式**：`start_rag_brain.bat`，等价于：
`python -m uvicorn knowledge.front.api.main:app --host 0.0.0.0 --port 8001`。

**目录结构**：

```
knowledge/
├── front/            # API 入口(main.py)、页面(chat.html/import.html)、schema、service、utils、temp_data(运行时临时)
├── processor/        # import_process 导入图 / query_process 问答图（LangGraph）
├── prompt/           # answer / hyde / 商品名(querry) / 导入(import) 提示词
├── tools/            # embedding、reranker、milvus、mongo_history、file_registry、mcp、llm
└── utils/            # bge_client、milvus_utils、minio_utils、llm_utils 等基础组件
```

## 3. 文档导入管线（import_process）

节点链（LangGraph，任务状态随节点推进，经 `/status/{task_id}` 查询）：

```
entry(文件类型检测)
  ├─ .pdf → pdf_to_md(MinerU 版面解析) ─┐
  └─ .md  ────────────────────────────┼→ md_img(图表理解) → document_split(切分)
                                        → item_name_recognition(产品名识别) → bge_embedding(嵌入)
                                        → import_milvus(入库)
```

| 节点 | 职责 | 说明 |
| :--- | :--- | :--- |
| entry | 类型检测 | `.pdf` → 置 `pdf_path`；`.md` → 置 `md_path`；其他类型抛 `ValidationError` |
| pdf_to_md | PDF 解析 | 调用 MinerU CLI 将 PDF 转为 Markdown（自动探测环境中的 mineru.exe），并设置图片模型所需环境 |
| md_img | 图表理解 | 处理 Markdown 中的图片：VLM 生成图片摘要（alt 文本），图片上传 MinIO 并改写为远程引用，检索展示不丢图 |
| document_split | 切片 | 统一换行符 → 按章节标题分段 → `RecursiveCharacterTextSplitter`（最大 2000 字，短段按 500 字下限合并） |
| item_name_recognition | 产品名识别 | LLM 从文档中抽取核心产品名/型号，BGE-M3 嵌入（dense+sparse）后写入 Milvus 产品名集合 |
| bge_embedding | 切片嵌入 | 每个切片经 BGE-M3 生成 1024 维 dense + sparse 双路向量 |
| import_milvus | 入库 | 集合不存在时自动创建（带索引），切片批量写入 Milvus 切片集合 |

**MD5 去重**：上传后先计算文件 MD5，命中 `file_registry`（MongoDB）则跳过导入并删除临时文件，
避免重复内容反复入库。

## 4. 智能问答管线（query_process）

```
item_name_confirm(商品名识别)
   ├─ 已可直接作答（如通用问询）→ answer_output
   └─ 需要检索 → multi_search ─┬─ search_embedding(向量检索)
                               ├─ search_embedding_hyde(先 HyDE 生成假设文档再检索)
                               └─ websearch(联网检索, MCP over HTTP, 失败降级空结果)
          → join(合并) → rrf(RRF 融合) → rerank(BGE-Reranker 精排) → answer_output(LLM 生成)
```

| 节点 | 职责 | 说明 |
| :--- | :--- | :--- |
| item_name_confirm | 商品名识别 | LLM 从用户提问中抽取产品名/型号（结合历史会话消解指代）；若无需检索即可作答则直接进入生成 |
| search_embedding | 向量检索 | 对产品名与问题做双路（dense + sparse）ANN 检索 Milvus 切片集合 |
| search_embedding_hyde | HyDE 增强 | 先用 LLM 生成"假设文档"，再以假设文档向量检索，提升召回 |
| websearch | 联网检索 | 通过 MCP over HTTP（DashScope）调用联网搜索工具；失败时降级为空结果，不影响主链路 |
| rrf | 结果融合 | 对多路检索结果做 Reciprocal Rank Fusion（k=60）合并 |
| rerank | 精排 | BGE-Reranker-large 对融合结果精排，截取 top_k 作为最终上下文 |
| answer_output | 生成回答 | 组装参考内容、历史会话与提问（`prompt/querry`、`prompt/answer`），调用 LLM 生成；支持流式（SSE）与非流式，回答附引用来源，并保存会话记录 |

**流式机制**：`POST /query`（`is_stream=true`）先建立 SSE 队列，随后后台线程执行问答图，
事件经 `GET /stream/{task_id}` 推送，避免 FastAPI BackgroundTasks 与无限流的冲突。

## 5. 数据层

### 5.1 Milvus（向量库）

集合名在 `knowledge/.env` 中配置（以下为默认示例值）：

| 集合 | 内容 | 字段要点 |
| :--- | :--- | :--- |
| `kb_chunks_v2` | 文档切片 | chunk_id / doc_id / title / parent_title / body / dense_vector(1024) / sparse_vector |
| `kb_item_names_v2` | 产品名索引 | 文档核心产品名，dense+sparse（供商品名识别召回/校验） |
| `kb_graph_entity_names_v2` | 实体名集合 | 预留（实体/图谱能力未启用） |

### 5.2 MongoDB（数据库 `knowledge`）

| 集合 | 用途 |
| :--- | :--- |
| `chat_message` | 会话历史消息（role/text/rewritten_query/item_names/ts），支撑 `/history`、`/sessions` |
| `file_registry` | 导入文件注册表（file_md5 唯一索引），实现 MD5 去重 |

### 5.3 MinIO（对象存储，bucket `knowledge`）

托管解析产物图片等二进制资源，供前端展示与检索引用。

### 5.4 本地临时目录

上传文件先落盘到 `knowledge/front/temp_data/{yyMMdd}/{task_id}/`，供导入管线读取；
该目录为运行时数据，已加入 `.gitignore`，不进入仓库。

## 6. 接口一览

| 方法 | 路径 | 功能 |
| :--- | :--- | :--- |
| GET | `/`、`/chat.html` | 问答页面 |
| GET | `/import.html` | 导入页（兼容跳转至问答页上传弹窗） |
| POST | `/query` | 提交提问（`is_stream` 区分流式/非流式），返回 session_id/task_id |
| GET | `/stream/{task_id}` | SSE 流式通道 |
| GET | `/history/{session_id}` | 会话历史（旧→新） |
| DELETE | `/history/{session_id}` | 清空会话 |
| GET | `/sessions` | 会话列表 |
| POST | `/upload` | 上传文档（触发导入图；MD5 重复返回跳过） |
| GET | `/status/{task_id}` | 任务状态与节点进度 |

## 7. 配置项（`knowledge/.env`）

> `.env` 为本机敏感配置，已加入 `.gitignore`，不随仓库分发；部署时按模板自行填写。

| 分组 | 键（示例） | 说明 |
| :--- | :--- | :--- |
| 大模型 | `OPENAI_API_KEY` / `OPENAI_API_BASE` / `LLM_DEFAULT_MODEL` / `LLM_DEFAULT_TEMPERATURE` | 问答/生成主模型（OpenAI 兼容） |
| 专用模型 | `VL_MODEL`（图片理解）、`ITEM_MODEL`（商品名识别）、`KG_MODEL`（预留） | 各环节独立模型配置 |
| 嵌入/重排 | `BGE_M3_PATH` / `BGE_DEVICE` / `BGE_FP16` / `BGE_RERANKER_LARGE` / `BGE_RERANKER_DEVICE` / `BGE_RERANKER_FP16` / `EMBEDDING_DIM` | BGE-M3 与 BGE-Reranker 路径与推理参数 |
| 向量库 | `MILVUS_URL` / `CHUNKS_COLLECTION` / `ITEM_NAME_COLLECTION` / `ENTITY_NAME_COLLECTION` | Milvus 连接与集合名 |
| MongoDB | `MONGO_URL` / `MONGO_DB_NAME` | 会话历史与文档注册表 |
| MinIO | `MINIO_ENDPOINT` / `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` / `MINIO_BUCKET_NAME` | 对象存储 |
| 联网检索 | `MCP_DASHSCOPE_BASE_URL` | 联网搜索 MCP 服务地址（可选） |

| 编号 | 问题 | 影响 | 改进方向 |
